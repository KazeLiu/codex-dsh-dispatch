# 开发文档

调研与设计日期：2026-11-17。当前仓库只有项目说明和开发文档，尚无插件入口、MCP 服务或设置界面；未安装插件、接入真实 DSH 或修改 Codex 配置。

## 1. 从一次委派到原会话返工

用户只向 Codex 描述需求。Codex 明确修改范围和完成条件，通过 MCP 把任务交给 DSH；DSH 使用自己的原生执行循环完成工作。Codex 收到结果后读取实际代码差异，发现问题则向原 DSH 会话继续发消息，直到可以交付。

例如，Codex 当前在 `D:\code\example` 中工作。首次派单时，插件自动找到或注册这个目录对应的 DSH 工作区，在其中创建本次 Codex 对话专属的 DSH 会话，并应用模型、思考强度和三档权限。后续补充与返工继续使用该会话，用户也能直接打开 DSH 查看和修改其设置。

这里的反馈不仅是最终回复，还包括正在执行、需要输入、失败和取消。工具不能返回一个“任务已提交”就让 Codex 误以为工作已经完成。

第一版以当前 Codex 回合内的等待和继续执行为目标。用户结束该回合或关闭客户端之后，普通 MCP 通知不作为自动启动新一轮 GPT 的保证；后台唤醒不纳入第一版。

## 2. 选择 DSH 插件直接提供 MCP

```text
Codex：理解需求、提供必要资料、派单、等待、审查实际差异
  │
  │ Streamable HTTP MCP，仅监听本机回环地址
  ▼
DSH 插件：请求校验、会话归属、回合关联、等待与结果投影
  │
  │ DSH 原生 Session Controller 与会话事件
  ▼
DSH：模型、工具、权限、会话持久化、原生执行循环
```

MCP 使用官方 SDK。模型执行、工具调用和会话历史使用 DSH 原有服务，不重新实现 Agent Loop，也不通过模拟点击、修改会话文件或抓取界面文本控制 DSH。

无需修改 Codex 源码，无需恢复此前撤回的 DeepSeek 模型目录、默认子代理或 Exa 配置。DSH 使用自己的模型与工具配置；Codex 的浏览器、MCP、技能和指令不会因为这条连接自动出现在 DSH 里。主对话应将必要的资料、图像解读和本次操作约束作为任务文字传入。

模型和思考强度按“本次明确指定 → 桥接保存的默认值 → DSH 默认值”选择。提供 FastCtx 式的轻量终端设置界面，不硬编码模型名称或思考强度。权限仅同步“请求批准 / 帮我批准 / 完全访问”三档；获取不到当前 Codex 对话的三档设置时，使用桥接设置中的默认权限。具体规则见第 4～6 节。

## 3. 已有依据与尚待确认的部分

### Agents Anywhere 证明了原生桥接路径

Agents Anywhere 的 DSH Bridge 在 DSH Host 中访问原生服务，向 Connector 提供创建会话、续聊、状态、历史、中断及交互处理。其本机通道使用 MeshCall，Windows 使用命名管道。

本机查阅的 `@agents-anywhere/dsh-bridge-next` 源码版本为 2.1.0，能看到 `sessionController.create`、`sessionController.prompt` 及 `session/event`、`agent/status`、`agent/assistant-stream` 的调用或订阅。公开仓库的主分支仍在更新，不能把它当作本机已安装 DSH 的精确版本。

本项目借鉴原生服务边界，不依赖 AA 云端、账号系统或 Connector。AA 内部的连接凭据按角色分权，不是供任意外部客户端调用 DSH 的通用凭据，不复制或挪用它们。

### DSH 当前官方源码已有关键会话接口

官方 Session Controller 源码提供 `create`、`prompt`、`cancel`、`state`、`wait` 和事件订阅。`prompt` 返回接收确认；`wait` 用于等待会话停止运行或出现待处理输入，并返回有界输出。两者不是同一个完成语义。

开始实现前，先读取用户实际安装的 DSH/SDK 版本和对应类型定义，确认插件安装入口、服务注入及方法签名。优先选择一个明确支持的版本，复用其原生 `wait`；若该版本没有此接口，应先确定基于原生事件的实现范围，不静默降级成扫描会话文件或反复启动 CLI。

### 工作区、模型目录和权限选择的源码依据

- 官方 `workspaceRegistry.create(path)` 会规范化现有目录的真实路径；相同路径复用原工作区，不改其标题。无需自行维护另一份工作区表或先遍历后创建。
- AA 通过 `llm.listProviders()`、`llm.listModels(providerId)` 和 `llm.resolveModelInfo(providerId, modelId)` 获取模型及各模型的思考强度，通过 `sessionController.selectModel` 应用选择。
- DSH 的 `permissionPresets.catalog()` 提供当前可选权限，`set` 和原生 `/permission` 命令提供设置路径。当前官方源码中的 `auto` 由自动审查集成动态提供，只能在该集成可用时用于会话，不能写入 DSH 普通 `defaultPreset` 字段。桥接可以保存自己的默认选择，创建会话后再通过原生接口应用。
- 普通 MCP 接入不保证提供 Codex 当前对话的标识或三档权限。实现时使用实际可取得的上下文，不把插件进程权限、全局配置或任务正文中的措辞当成当前对话权限；缺失权限按第 6 节使用已配置默认值，不阻塞其他能力。

## 4. 首次派单时关联工作区和专属会话

自动关联在第一次调用 `dsh_start` 时发生，不监听“打开 Codex 对话”事件。它分为两层：**同目录共享 DSH 工作区，同一 Codex 对话继续自己的 DSH 会话。**

1. Codex 传入本次任务的绝对工作目录；Git worktree 使用实际 checkout 路径，不擅自切回主仓库。无项目归属但明确提供工作目录时，也按相同规则处理；没有目录则要求调用方补充，不使用 DSH 进程的启动目录。
2. 通过原生 `workspaceRegistry.create(cwd)` 注册或复用工作区，采用 DSH 的路径规范化和去重规则。目录必须在 DSH 所在设备上已存在且可访问；“不存在则创建”指创建工作区记录，不是创建、复制或克隆磁盘目录。
3. 创建本插件专属的 DSH 会话并关联该工作区。目标 SDK 支持 `create({ workspaceId })` 时优先使用；否则按已核对的 `create({ cwd })` 加 `workspace.attachSession(sessionId)` 路径实现，不能同时传互斥字段。
4. 在提交第一条任务前应用模型、思考强度和权限。任一配置被 DSH 拒绝时，不在错误配置下继续提交任务，返回错误及已创建会话的定位信息。
5. 返回工作区 ID、会话 ID 和规范化目录。后续调用 `dsh_send`，不因同目录另有会话就接管它，不把两个 Codex 对话合并进同一 DSH 会话。

有宿主提供的稳定 Codex 对话标识时，可以保存其与 DSH 会话的最小关联；没有时，由调用方保留首次返回的 DSH 会话 ID 并用于续聊。不能把目录、进程 ID 或 MCP 连接 ID 冒充 Codex 对话标识。`dsh_start` 的相同请求 ID 仍按第 7 节幂等恢复，不重复创建会话。

## 5. 设置界面管理模型、思考强度和默认权限

第一版提供 `dsh-mcp-bridge config` 打开的轻量终端设置界面（TUI），无需独立浏览器后台或新的 Electron 应用。下方为拟定界面，不代表命令已可用：

```text
DSH MCP Bridge                     已连接：desktop

默认模型        [跟随 DSH 默认设置                 ▾]
思考强度        [跟随模型默认设置                  ▾]
默认权限        [请求批准                          ▾]

[刷新列表]  [保存默认值]  [退出]
```

### 选择项来自当前 DSH，保存后作用于新会话

- 模型列表来自当前连接的 DSH Profile，只列出其实际提供的供应商和模型。同名模型要显示供应商，保存稳定的供应商 ID 和模型 ID，不保存显示名称作为唯一标识。
- 选定模型后读取该模型的能力，仅展示其支持的思考强度。没有可选强度时禁用该项；切换模型时重置为“跟随模型默认设置”，不沿用上一个模型的强度。
- 选择“跟随 DSH 默认设置”时，不固定模型或思考强度，沿用 DSH 为新会话解析出的设置。选择具体模型但不指定强度时，沿用该模型经 DSH 解析出的默认强度。
- 默认权限提供“请求批准 / 帮我批准 / 完全访问”，规则见第 6 节。桥接初始默认值为“请求批准”。不可用项显示原因并禁止选择，不假造可用能力。
- 打开界面或点击“刷新列表”时读取最新目录。服务不可用时显示连接错误，不能伪造模型列表；已保存但当前失效的模型、强度或权限保留为失效状态，提示重新选择，不自动换模型或放宽权限。
- 保存成功后，新建会话立即使用新默认值，无需重启 DSH；已有会话及正在运行的回合保持原设置。用户可直接在 DSH 修改已有会话的模型、思考强度和权限，桥接续聊不重复覆盖它们。

模型与思考强度作为同一个选择保存。本次任务明确指定其他模型时，不混入已保存模型的思考强度；选定模型后再依据其能力解析本次明确指定的强度或模型默认值。无覆盖时依次使用桥接默认选择、DSH 默认选择。

### 设置客户端复用插件服务与持久化

TUI 是当前 DSH 插件的配置客户端，通过同一本机认证通道读取目录、读取及保存默认值；不另外启动 DSH 实例，不复用 AA Connector，也不读取模型密钥。配置接口的具体路由随实际插件 SDK 定稿，任务工具仍保留第 7 节的四个入口。

由插件负责校验与持久化设置，优先复用 DSH 提供的插件设置或存储能力；TUI 不直接改写 DSH Profile、全局默认模型或会话文件。桥接默认值只影响本插件新建的会话，不改变用户从 DSH 手动创建会话时的默认设置。不要让 TUI 与插件各维护一份配置。

## 6. 权限只同步三档，读不到时使用默认值

本项目的权限需求仅指界面中的三种操作模式，不扩展为完整复制 Codex 沙箱、网络、目录白名单、工具、技能或组织策略。

| 桥接三档模式 | 行为 | DSH 对应能力 |
| --- | --- | --- |
| `ask`：请求批准 | 按 DSH 策略请求用户批准 | 使用目标版本中对应的原生人工审批预设 |
| `auto`：帮我批准 | 由 DSH 原生自动审查能力判定，仍可能转人工 | 仅在原生自动审查集成可用并通过准入检查时选择 |
| `full`：完全访问 | 使用 DSH 的完全访问模式 | 使用目标版本中对应的原生完全访问预设 |

表中的 `ask / auto / full` 是桥接自己的语义值，不是三个可以直接写入任意 DSH 版本的预设 ID。实现时核对目标 SDK 的权限目录与实际预设；不能只按翻译后的显示名称猜测，也不能把“帮我批准”等同于 `approval=never` 或完全访问。

### 新会话的权限选择顺序

1. 能从当前调用的真实会话上下文获取 Codex 三档模式时，传入结构化 `sourcePermission`，并映射到 DSH 对应模式。
2. 无法取得当前三档模式时，省略 `sourcePermission`，使用设置界面保存的默认权限。
3. 尚未保存默认权限时，使用桥接初始值“请求批准”。返回结果同时说明采用了源会话、桥接默认值还是初始值。

读取不到源权限是正常使用路径，不反复要求用户提供 Codex 配置，不以此阻塞工作区关联与任务派发。传入非法值、已保存设置失效或 DSH 不支持所选模式则明确报错，不能把这些错误伪装成“读取不到”后悄悄换档。

“帮我批准”保存为**桥接的默认意图**，创建会话后通过原生权限接口启用，不写入 DSH 不接受它的普通 `defaultPreset` 字段。自动审查组件不可用时禁止选择并说明原因，不自动安装插件，不由桥接实现一个新的审批模型或无条件回复批准。

### DSH 中的手动修改保持有效

新建会话时初始化权限，后续 `dsh_send` 不重复应用默认权限。同一源权限值再次传入也不重写 DSH，保证用户在 DSH 手动改档后，正常续聊不会把它改回去。仅当后来实际取得的 Codex 三档值与上次取得的值不同，或此前从未取得源权限而现在取得时，才在下一次提交任务前同步一次；桥接保存最后取得的源值用于比较，不监听或中途改写正在执行回合的权限。

这三档不替代任务授权。用户未授权测试、安装、推送或破坏性操作时，仍将限制写入派单文字。“请求批准”或自动审查升级到人工处理时返回 `needs_input`，由用户在 Codex 或 DSH 中完成交互，不由桥接一律批准。

## 7. 第一版拟提供四个任务工具

以下是本项目的设计名称和语义，尚未注册为可调用工具；参数细节在目标 SDK 核对后定稿。

| 工具 | 主要输入 | 返回与职责 |
| --- | --- | --- |
| `dsh_start` | 绝对工作目录、完整任务文字、稳定请求 ID；可选源权限及本次模型选择 | 复用或注册工作区，创建专属会话并应用设置后提交任务，返回定位信息、有效配置及接收状态 |
| `dsh_wait` | 会话 ID、请求 ID、输出游标、等待时长 | 等待该请求对应回合的结果或需要输入的状态，返回新增输出及下一游标 |
| `dsh_send` | 会话 ID、补充文字或交互回复、新的稳定请求 ID；可选源权限 | 在原会话继续执行、返工，按第 6 节处理源权限变化，或回答对应的待处理交互 |
| `dsh_cancel` | 会话 ID | 显式请求取消当前任务，并返回取消请求是否被接受 |

普通消息与交互回复是互斥输入。交互回复必须携带原生交互标识、答案或用户已明确批准的选择，调用 DSH 原生交互服务；不能把它作为普通 prompt 发送后假装审批已完成。具体标识和连接所有权规则须以目标 SDK 为准。

`dsh_start` 至少返回 `workspaceId`、`sessionId`、`cwd`、`requestId`、`status`，以及 DSH 实际接受的模型、思考强度、三档权限和各自配置来源。跟随 DSH 默认值时返回解析后的实际选择，不只返回“默认”；实际选择暂时不可读时明确标记未知。续聊和等待结果读取 DSH 当前有效状态，不把创建时缓存当成用户手动修改后的现值。

对外返回以可读文本和结构化结果为主。完成结果保留最终回复及会话定位信息；不把完整历史、全部工具输出或模型内部推理反复塞回 Codex。需要进一步审查时，Codex 读取实际代码与差异，不只相信 DSH 的完成摘要。

### 状态必须反映真实执行

| 状态 | 含义 |
| --- | --- |
| `accepted` | 请求已被 DSH 接收，尚不能判断完成 |
| `running` | 对应回合仍在执行 |
| `needs_input` | 存在待处理提问或审批，需要明确返回具体内容 |
| `completed` | 对应回合正常结束，返回可取得的结果及输出缺失等实际情况 |
| `failed` | 对应回合失败，返回错误与可继续定位的会话信息 |
| `cancelled` | 已确认对应回合被取消；仅接收取消请求时不能提前报告此状态 |

必须关联本次请求和对应回合，不能仅凭 HTTP 成功、工具接收确认或会话暂时空闲认定任务完成。原生回合正常结束也不等于业务验收通过，最终验收由 Codex 审查和用户授权的操作决定。

### 等待、重试与恢复

- `dsh_start` 和 `dsh_send` 使用稳定请求 ID。网络响应丢失时，先核对原生接收记录，避免重复执行写入任务。
- 等待应有时限并按游标返回增量。等待到期只表示尚未拿到终态，不自动重新派单或取消 DSH 任务。
- 取消一个 MCP 等待请求只结束等待；取消执行必须走显式的 `dsh_cancel`。
- 插件重载后使用 DSH 原生会话恢复定位。若必须保存请求与会话的归属关系，只保存最小元数据，不复制另一份会话数据库。
- DSH 或插件不可用时明确报错，不回退到 Codex 原生 DeepSeek 子代理或自动启动另一个 DSH 实例。

## 8. 避免重演抢写与长时间空转

第一版每个规范化工作目录同一时间只允许本插件派发的一个写入任务；其他请求明确返回占用信息，不静默并行。这个限制只约束本插件派发的任务，不能锁住用户或其他程序的文件操作。

同一处代码只保留一个写入负责人。DSH 执行时，Codex 可以阅读和审查，但不同时改写它负责的代码。审查发现问题先通过 `dsh_send` 交回；需要接管时先确认 DSH 已停止写入。

派单文字应包含：目标、工作目录、允许修改的范围、必要资料、操作限制、完成条件与交付要求。例如用户没有授权测试时，应明确写入“不新增、修改或运行测试，也不启动应用或浏览器”。权限仍由 DSH 原生策略执行，任务文字不替代权限控制。

DSH 长时间没有有效进展时，返回最近可观察的操作、时间和阻塞信息，由 Codex 判断是否补充资料或中止。第一版不新增自动重试、自动换模型或自动重启运行时策略。

## 9. 本机连接与授权

- MCP 服务只监听本机回环地址，并校验客户端认证；不默认暴露局域网或公网端口。
- 为本插件使用独立认证材料，经宿主支持的凭据或环境注入方式配置，不复用 AA、OpenAI 或浏览器登录态。
- 凭据不进入源码、Git、任务正文和日志。诊断日志记录必要的请求标识、状态和错误码，不记录模型密钥或整个任务正文。
- 只操作本插件创建或用户明确授权接管的 DSH 会话，不默认接管用户正在进行的聊天。
- 三档权限交给 DSH 原生策略执行；“帮我批准”由其原生自动审查处理。仍需人工审批或回答时返回 `needs_input`，通过 `dsh_send` 的交互回复分支路由回 DSH；核对目标 SDK 的连接所有权和单次交互有效性，不能代替用户无条件批准。
- 设置界面的读写接口与任务接口采用相同的本机认证要求；保存默认权限属于用户配置操作，不能让任意网页或未认证客户端更改。
- Host 卸载时关闭本插件拥有的 MCP 监听和订阅，不终止已有 AA Connector、其他 DSH 会话或非本项目创建的进程。

## 10. 开发顺序与完成条件

1. **核对实际 SDK 并建立插件入口。** 记录 DSH、插件 API、Node.js 版本及实际类型；确认会话、工作区、模型目录、权限预设、自动审查、设置持久化与交互服务。当前设备已安装 DSH NEXT，优先检查现有安装及 desktop Profile，不先安装另一套 DSH。源权限获取不到就进入默认值路径，不为它阻塞整个实现。
2. **实现原生会话闭环。** 建立本机 MCP 服务和四个任务工具，串行完成工作区复用或注册、专属会话创建、发送、等待、原会话续聊和取消。以 DSH 原生持久化为事实来源。
3. **接入配置解析和权限映射。** 获取真实模型及各自思考强度，解析三层模型选择与源权限或默认权限；在首次 prompt 前应用配置，返回有效选择及来源。保留 DSH 手动修改，处理源权限后续变化和配置失效，不修改 DSH 全局默认值。
4. **完成 TUI 与交互路径。** 提供配置入口、真实连接状态、动态选择、刷新和保存；实现提问、人工审批、失败、等待超时和断线状态。原生自动审查与人工交互走各自路径，不以全部自动批准代替。
5. **获得验证授权后联调。** 先用只读任务确认链路，再用隔离目录中的小修改确认 Codex 能审查实际差异并让原 DSH 会话返工；按下方完成条件核对工作区、设置、权限、等待和恢复行为。
6. **完成可安装交付。** 给出插件及配置命令的安装与卸载、Codex MCP 配置、支持的确切版本和已验证范围。真实闭环通过前，不声称插件可用或发布正式版本。

### 验收时需要看到的行为

- 同一路径连续派单不重复注册工作区；不同路径的同名项目、不同 worktree 不混淆。两个 Codex 对话可共享工作区，但各有自己的 DSH 会话，返工回到原会话。
- 没有桥接模型默认值时跟随 DSH；保存具体模型和强度后，新会话使用该组合；本次明确指定时使用本次选择。切换模型不沿用不支持的强度，保存失效配置或启动时遇到失效配置会明确报错。
- 能取得源权限时三档对应生效；取不到时使用保存的默认值，首次未配置时使用“请求批准”。“帮我批准”确实调用 DSH 原生审查而不是全部放行，组件不可用时明确提示。
- TUI 保存后不用重启即可影响新会话，不改已有会话或 DSH 全局默认值。在 DSH 手动修改已有会话后，正常续聊保留选择；源权限真正变化时才按第 6 节再次同步。
- 接收、运行、需要输入与终态可区分；等待超时不会重复派单或取消任务，取消和重连不误报完成，同一请求重试不生成第二份执行。
- 仅本机、经过认证的客户端可以派单和保存设置，凭据不进入任务正文、源码或日志。

当前不新增或运行测试，不启动应用进行联调，不安装依赖或配置真实凭据。后续实现与验证分别遵循用户的实际授权。

## 11. 第一版之外

暂不做五路并行、独立 Web 管理界面、跨设备云服务、打开 Codex 对话即创建 DSH 会话、自动唤醒已结束的 Codex 会话、完整复制 Codex 沙箱策略、替代 DSH 工具系统、模型网关或桥接自建审批模型。第一版包括轻量 TUI、工作区自动关联、模型默认值和三档权限选择，把单任务、可等待、可续聊、可取消的闭环做扎实。
